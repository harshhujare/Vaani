## 1. Architectural Boundary & Core Principles

```
┌────────────────────────────────────────────────────────┐
│                        AI LAYER                        │
│  • Speech-to-Text (ASR)                                │
│  • Unstructured Profile Extraction                     │
│  • Semantic Normalization                              │
│  • Natural-Language Explanation Generation             │
└───────────────────────────┬────────────────────────────┘
                            │ Structured Facts Only
                            ▼
┌────────────────────────────────────────────────────────┐
│                  DETERMINISTIC ENGINE                  │
│  • Hard Eligibility Gates (Pass / Fail)                │
│  • 100-Point Heuristic Scoring Formula                 │
│  • Multi-Tier Ranking & Diversity Filters              │
│  • Skill Gap Set Subtraction                           │
│  • Geospatial Distance Matching                        │
└────────────────────────────────────────────────────────┘
```

* **No Black-Box Decisions:** An LLM does not choose the course or assign the score[cite: 1].
* **Traceable & Auditable:** Every recommendation generates an explicit mathematical breakdown for jury and government audits[cite: 1].
* **Grounded Facts:** Qualification metadata, eligibility rules, and center rosters are queried strictly from PostgreSQL, not generated by an LLM[cite: 1].

## 3. Detailed Step-by-Step Breakdown

### Step 1: Voice Ingestion & Entity Extraction
* Converts speech to text using regional speech engines[cite: 1].
* The extraction LLM converts unstructured statements into raw attributes (`occupation`, `experience_years`, `raw_skills`, `assets`, `education`, `interests`, `location`, `preference`)[cite: 1].

### Step 2: Canonical Normalization
* Natural language skill descriptions vary widely (e.g., *"कपडे शिवणे"*, *"सिलाई"*, *"dress alteration"*)[cite: 1].
* Uses an alias table and semantic lookup to map inputs to verified Canonical Skill IDs in the database[cite: 1].
* Unrecognized or hallucinated skills outside the database are excluded[cite: 1].

### Step 3: Candidate Retrieval (Dual Funnel)
To evaluate thousands of national qualifications efficiently[cite: 1]:
* **SQL Broad Filter:** Queries active qualifications in matching sectors[cite: 1].
* **Vector Search (`pgvector`):** Matches profile context against qualification descriptions via cosine similarity to catch adjacent roles[cite: 1].
* **Merge:** Aggregates both pipelines into a candidate pool of 50–100 qualifications[cite: 1].

### Step 4: Hard Eligibility Gate (Binary Evaluation)
Before any scoring takes place, strict prerequisite checks eliminate invalid courses[cite: 1]:
* **Education:** `beneficiary.education >= qualification.min_education`[cite: 1]
* **Experience:** `beneficiary.experience >= qualification.min_experience`[cite: 1]
* **Course Validity:** `qualification.is_active == True`[cite: 1]

### Step 5: 100-Point Heuristic Scoring Model
Each eligible candidate qualification is scored from $0$ to $100$[cite: 1]:

$$\text{Final Score} = \sum (\text{Component Score} \times \text{Weight})$$

| Component | Weight | Criteria & Measurement Basis |
| :--- | :---: | :--- |
| **Skill Compatibility** | **30%** | Weighted overlap between user skills and required course standards[cite: 1]. |
| **Interest Alignment** | **20%** | Semantic match between user goals and qualification outcomes[cite: 1]. |
| **Experience Relevance** | **15%** | Alignment between past working years and subject area[cite: 1]. |
| **Education Match** | **10%** | Direct baseline compliance with educational prerequisites[cite: 1]. |
| **Asset Compatibility** | **10%** | Ownership of necessary functional tools (e.g., sewing machine, basic tools)[cite: 1]. |
| **Location / Accessibility** | **5%** | Distance scale ($100$ points for $<5\text{ km}$, scaled down to $30\text{ km}$)[cite: 1]. |
| **Employment Preference** | **5%** | Preference match: Self-employment vs. Wage employment[cite: 1]. |
| **Batch Availability** | **5%** | Open seats in the nearest upcoming training cycle[cite: 1]. |

### Step 6: Ranking & Diversity Filtering
* Eligible qualifications are sorted in descending order by final score[cite: 1].
* A diversity filter prevents redundant recommendations by assigning pathways into three distinct tiers[cite: 1]:
  * **Best Match:** Closest fit to current skills and profile[cite: 1].
  * **Growth Path:** Slightly higher NSQF level aligned with future interests[cite: 1].
  * **Alternative Option:** Practical, viable lateral pathway[cite: 1].

### Step 7: Skill Gap Extraction
* Performs mathematical set subtraction against course competencies:

$$\text{Skill Gaps} = \text{Required Competencies} \setminus \text{Possessed Competencies}$$

* Categorizes the output into **Strengths** (possessed) and **Gaps** (to be trained)[cite: 1].

### Step 8: Nearest Training Center Matching
* Computes Haversine distance from the beneficiary coordinates to all authorized centers running the selected qualification[cite: 1].
* Selects the closest facility with active seat capacity[cite: 1].

### Step 9: Guardrailed Explanation Generation
* The LLM is supplied with the raw numbers, matched skills, gaps, and center details as strict context[cite: 1].
* Generates a 2-sentence rationale in the beneficiary's local language explaining why the course was selected[cite: 1].
* Guardrails prohibit hallucinating placement guarantees or unauthorized stipends[cite: 1].

## 5. Repository Directory Structure

```text
services/recommendation_engine/
├── core/
│   ├── config.py              # Tunable scoring weights and parameters
│   └── exceptions.py          # Custom validation and error handlers
│
├── pipeline/
│   ├── 01_normalizer.py       # Resolves natural text to Canonical Skill IDs
│   ├── 02_retriever.py        # SQL sector filter + pgvector semantic search
│   ├── 03_eligibility.py      # Hard prerequisite gatekeeper
│   ├── 04_scorer.py           # 100-point multi-factor calculator
│   ├── 05_ranker.py           # Sorter & diversity pathway categorizer
│   ├── 06_gap_analyzer.py     # Competency set subtraction
│   ├── 07_spatial_matcher.py  # Haversine distance calculator
│   └── 08_explainer.py        # Guardrailed LLM explanation generator
│
├── data/
│   ├── seed_qualifications.json  # 30–50 curated NQR qualification definitions
│   ├── seed_skills.json          # Canonical Skill Taxonomy & alias dictionary
│   └── seed_centers.json         # Mock registry of training centers
│
├── tests/
│   ├── test_eligibility.py    # Verifies prerequisite rejections
│   ├── test_scoring.py        # Validates mathematical output consistency
│   └── test_engine_flow.py    # End-to-end integration test
│
└── engine.py                  # Orchestrator executing the 8 pipeline stages
```
